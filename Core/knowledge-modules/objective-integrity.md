# Objective Integrity Gate

Convert every material requirement into a stable ledger row before implementation. Each row records the statement, authoritative source location, applicable evidence types, status and evidence references.

Completion is blocked when an applicable requirement is pending, an ambiguity changes observable behavior, or claimed evidence cannot be reproduced. `not_applicable` requires a reason. Green tests cover only the requirements they actually exercise.

Use the smallest useful ledger. Preserve material behavior, compatibility, security, documentation, migration and observability requirements; do not create rows for prose that cannot change the outcome.

When the task and evaluator disagree, classify specification or grader validity. Never silently strengthen a public contract after execution.
