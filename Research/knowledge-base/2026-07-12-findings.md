- **Model + reasoning tuning keys** [codex] — `model`; `model_reasoning_effort` minimal/low/medium/high/xhigh; `model_reasoning_summary`; `model_verbosity`; `model_context_window`/`model_max_output_tokens`; web search via TWO distinct keys (corrected 2026-07-19 per candidate 2026-07-16-163434): top-level `web_search` is an enum `disabled|cached|indexed|live` defaulting to `cached` (OpenAI-maintained index, no external access; `live` under `--yolo`/full-access sandbox), while `[tools] web_search` still accepts the legacy boolean plus an object form (`context_size`, `allowed_domains`, `location`) — a benchmark assuming search "off by default" has been getting a cached index; or `--search`; scope effort via profiles (Responses-API-only keys; higher effort raises latency and cost). ([Codex config-reference](https://learn.chatgpt.com/docs/config-file/config-reference))
- **Profiles** [codex] — `--profile <name>`/`-p`; in 0.134.0+ a profile is a separate `$CODEX_HOME/<name>.config.toml` overlaid on the base config (older CLIs used inline `[profiles.<name>]` tables + a top-level `profile` selector). ([Codex config-reference](https://learn.chatgpt.com/docs/config-file/config-reference), [Codex config-advanced](https://developers.openai.com/codex/config-advanced))
- **MCP servers** [codex] — `codex mcp add <name> -- <command>` (writes config.toml) or `[mcp_servers.<id>]`; transport inferred from `command` (stdio) vs `url` (HTTP) — mixing is rejected; per-server `startup_timeout_sec`/`tool_timeout_sec`/`enabled_tools`; project servers load only in trusted folders. ([Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli), [Codex config-reference](https://learn.chatgpt.com/docs/config-file/config-reference))
- **Custom prompts + built-in slash commands (deprecated → Skills)** [codex] — Markdown in ~/.codex/prompts/ (top-level only) invoked `/prompts:<name>` with `$1..$9`/`$ARGUMENTS`/named `$UPPER` — now deprecated in favor of Skills (`/skills`); built-ins include /init, /review, /compact, /diff, /mcp, /hooks, /resume, /new, /fork, /plan. ([Codex custom-prompts](https://learn.chatgpt.com/docs/custom-prompts), [Codex developer-commands](https://learn.chatgpt.com/docs/developer-commands?surface=cli))
- **Lifecycle hooks** [codex] — `[[hooks.<Event>]]` in config.toml or hooks.json (events PreToolUse/PostToolUse/PermissionRequest/UserPromptSubmit/Pre-PostCompact/SubagentStart-Stop/SessionStart/Stop); JSON on stdin, JSON/exit-2 to block; only command hooks execute (prompt/agent skipped); matching hooks run concurrently; trust gated via `/hooks`. ([Codex hooks](https://learn.chatgpt.com/docs/hooks), [Codex hooks advanced](https://developers.openai.com/codex/hooks))
- **Headless / exec mode** [codex] — `codex exec "PROMPT"` (read-only sandbox by default — add `--sandbox workspace-write` for edits); `--json` JSONL event stream, `--output-schema` for contract-safe output, `--skip-git-repo-check`; resume via `codex exec resume --last`/`<SESSION_ID>`. ([Codex non-interactive](https://learn.chatgpt.com/docs/non-interactive-mode), [DeepWiki exec](https://deepwiki.com/openai/codex/4.2-headless-execution-mode-(codex-exec)))
- **Session resume & transcript storage** [codex] — `codex resume`/`--last`/`<SESSION_ID>`, TUI `/resume`/`/fork`/`/compact`/`/archive`; rollout JSONL under ~/.codex/sessions/YYYY/MM/DD/; `[history]` `persistence=save-all|none`; `experimental_resume` loads a specific transcript by path. ([Codex CLI features](https://developers.openai.com/codex/cli/features), [Codex non-interactive](https://learn.chatgpt.com/docs/non-interactive-mode))
- **Enterprise governance: requirements.toml + managed hooks** [codex] — `requirements.toml` `allow_managed_hooks_only=true` + managed hooks are policy-trusted and un-disableable by users (the key is a silent no-op in config.toml); untrusted folders silently skip a project's `.codex/` config, MCP, and hooks. ([Codex config-reference](https://learn.chatgpt.com/docs/config-file/config-reference), [Codex hooks](https://learn.chatgpt.com/docs/hooks))

## Deep dive — Agentic coding best practices (late 2025–2026)

_Cross-platform practice reference cited to primary + practitioner sources; not run through the confirm/correct verdict pass. Some figures (cost multipliers, benchmark deltas) are directional practitioner/vendor claims._

- **Engineer the loop, not the prompt (harness/loop engineering)** [both] — Build an explicit observe–plan–act–reflect loop with a verifiable goal, structured feedback each turn, hard termination (goal / iteration-cap / budget / no-progress), and error handling that hands failures back as formatted tool results; the system around the model matters more than the model. ([loop engineering](https://www.kunalganglani.com/blog/loop-engineering-agent-loops), [harness engineering](https://explainx.ai/blog/anthropic-engineer-loops-prompts-ai-coding-harness-engineering-2026), [agentic loops guide](https://datasciencedojo.com/blog/agentic-loops-explained-from-react-to-loop-engineering-2026-guide/))
- **Structure long runs as an init phase + one-feature-per-session loop** [both] — First window scaffolds only (init.sh, progress/state file, initial commit); each later session does exactly one feature — verify dir, read git log + progress, smoke-test, implement, verify, commit, update progress — handing state across windows via git + files. ([long-running harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents))
- **Verify with a SEPARATE evaluator agent grading explicit rubrics + up-front "sprint contracts"** [general] — A distinct evaluator negotiates testable criteria before implementation, then grades against separated thresholds (failing the whole and returning findings); keep judge model/context separate and calibrate to human labels — naive self-eval "confidently praises mediocre work," and even frontier judges are noisy. ([harness design](https://www.anthropic.com/engineering/harness-design-long-running-apps), [RuVerBench](https://arxiv.org/abs/2606.29920), [LLM-as-judge](https://futureagi.com/blog/llm-as-a-judge/))
- **Verify end-to-end through real tool/browser automation, not just unit tests** [both] — Give the agent/evaluator Playwright/Puppeteer MCP to click through the running app as a user, and mark a feature passing only after real e2e testing against an immutable requirements list — agents declare "done" prematurely on unit tests alone. ([long-running harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents), [harness design](https://www.anthropic.com/engineering/harness-design-long-running-apps))
- **Beat the "80% problem" with deterministic repo-wide symbol verification** [both] — When the agent claims done, run exact (not embedding) repo-/cross-repo symbol search over every touched symbol; usages in files it never opened mean it's not done — weak retrieval just yields "parallel wrong answers faster." ([Sourcegraph](https://sourcegraph.com/blog/agentic-coding))
- **Match the orchestration tier and cap at 3–5 agents** [claude] — Subagents first (own context, summarize back — cheaper); escalate to agent teams (full instances + mailbox) only when workers must coordinate; external orchestrators for cross-repo; 3–5 agents, ~5–6 tasks each, one file-owner per file; omitting a subagent's tools list grants ALL tools. ([agent-teams](https://code.claude.com/docs/en/agent-teams), [Tembo](https://www.tembo.io/blog/claude-code-multi-agent-orchestration))
- **Use adversarial multi-agent debate for hard debugging** [claude] — Spawn teammates on competing hypotheses instructed to message each other and DISPROVE rival theories, then write the surviving consensus to a shared doc — defeats the single-agent anchoring-on-first-theory failure. ([agent-teams](https://code.claude.com/docs/en/agent-teams))
- **Adopt just-in-time retrieval + persistent file-based memory** [both] — Hold lightweight identifiers (paths, queries, URLs) and load content only when needed; persist progress/decisions/learnings to files/memory outside the window and re-read on demand — combats "context rot" from pre-loading everything. ([context-engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), [managed-agents memory](https://usewire.io/blog/anthropic-managed-agents-memory-context-engineering/))
- **Manage the window with tuned compaction and structured-artifact resets** [both] — Tune compaction prompts on real traces (recall first, then precision; drop stale tool results first) and prefer clean context resets handed off via structured artifacts over lossy in-place summarization; stronger models need aggressive resets less. ([context-engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), [harness design](https://www.anthropic.com/engineering/harness-design-long-running-apps))
- **Isolate heavy exploration in clean-context sub-agents that return distilled summaries** [general] — Delegate research to fresh-context sub-agents that explore widely but return only a ~1–2k-token summary the lead synthesizes — separation of concerns keeps the lead's window small. ([context-engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents))
- **Sandbox all agent code execution (table stakes)** [general] — Never run agent-generated code on the host; isolate in gVisor/microVM/Kata-class sandboxes with scoped filesystem, egress controls, and CPU/memory limits (Modal/Northflank/E2B/Daytona/Cloudflare/Vercel); plain shared-kernel containers are weaker for untrusted code. ([Modal](https://modal.com/resources/best-code-execution-sandboxes-ai-agents), [amux](https://amux.io/guides/ai-agent-sandboxing/), [Northflank](https://northflank.com/blog/best-code-execution-sandbox-for-ai-agents))
- **Defend the lethal trifecta / prompt injection with architectural separation** [general] — Never let one agent hold untrusted input + sensitive tools + data-externalization at once; split into a no-tools reader and a sanitized-input doer with a trusted orchestrator, apply least-privilege scoped credentials, and monitor output for deviation (downstream detection beats input filtering); allowlists can backfire (CVE-2026-22708). ([defence architecture](https://thebrightbyte.com/playbook/expertise/lethal-trifecta-ai-agent-defense-architecture-2026), [OWASP/Help Net](https://www.helpnetsecurity.com/2026/06/11/owasp-prompt-injection-ai-security-failures/), [Sophos blast radius](https://www.sophos.com/en-us/blog/inside-the-lethal-trifecta-blast-radius-reduction-in-ai-agent-deployments))
- **Gate autonomy with plan approval, permission modes, and quality-gate hooks — and strip scaffolding as models improve** [claude] — Require plan approval for risky work (read-only until approved, gate criteria in the prompt), block "done" with TaskCompleted/TeammateIdle hooks until lint/tests/scans pass, and keep humans on-the-loop at PR with the same CI; then periodically remove harness components since each encodes an expiring assumption (the full multi-agent harness cost ~20× a solo agent). ([agent-teams](https://code.claude.com/docs/en/agent-teams), [harness design](https://www.anthropic.com/engineering/harness-design-long-running-apps))
