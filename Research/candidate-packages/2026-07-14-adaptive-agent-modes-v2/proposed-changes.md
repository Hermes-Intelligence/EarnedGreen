# Proposed changes - Adaptive Agent Modes v2

Status: evaluated Candidate, not Stable. No commit, push or provider call was performed.

## Remove or supersede

- Raw keyword routing that treated `source`, `email`, `index` and `production` as sufficient context.
- The misleading `core-router-enforcement` label whose only hard control was protected-file comparison after execution.
- Quality conclusions from hidden checks not entailed by the public task.
- The assumption that a Full arm costs one call even though it requires an independent verifier.
- Volatile model IDs in durable mode policy.

## Add

- Five adaptive runtime modes with explicit ceilings, escalation triggers, capability profiles and human boundaries. Selection uses three dimensions (modes schema 3): consequence (blast radius) is the only dimension that can reach `full` and its human gate; breadth (width of change) and continuity (session boundaries) each cap at `mode-3-assured`, whose durable checkpoints, impact map and adversarial verification absorb wide or resumable work. Action intent is explicit, so planning, explanation and dry runs do not acquire Full merely by mentioning deployment or credentials. Runtime Vanilla is advisory/read-only; the coding benchmark baseline is a distinct unscaffolded task-only `vanilla-control`. The numeric ceilings are declared `hypothesis-pending-benchmark` and the per-mode eval arms exist to calibrate them.
- Precision Knowledge Router v2 with strong phrases, co-occurrence anchors, negative matches and per-mode budgets.
- Objective Integrity Engine covering bullets, the task objective and normative prose, plus stable IDs and ambiguity detection.
- Executable fail-closed evidence gate with Windows and POSIX launchers; Full additionally requires human scope approval and independent verification.
- Provider-independent profile resolver that blocks automation when the weekly catalog is stale.
- Observable context telemetry emitted for every graded adaptive run; it reports only selected/opened markers visible in provider events and never claims access to private reasoning.
- Executable Mode 3+ impact maps, adversarial challenge runs and conditional checkpoint/handoff gates; Mode 1 receives a lossless compact ledger and the minimal Core.
- Failure attribution separating agent, router, enforcement, specification, grader and infrastructure failures.
- Versioned repairs for the two invalid historical fixture checks and complete check-to-contract traceability for six real-world fixtures.
- A five-arm ablation whose six provider calls are approval-locked, have no automatic replacements or follow-up and count the Full verifier honestly.
- Human Markdown/PDF guide and promotion payload with rollback hashes.
- A Candidate-only `adaptive-contract-evolution-v2` boundary fixture with public anchors, a per-check-isolated hidden grader, ordered 50/72/78/100 deterministic controls (including a reject-on-miss semantic control), a 100% reference and an independently authored second reference.
- A harder successor `adaptive-contract-evolution-v3` boundary fixture (`implementation/mode-boundary-fixture-v3/`, admission verdict PASS) whose separation lives in three scaffolding-caught dimensions -- an omission-prone rare-path requirement (`degraded-path`), an indirectly reached consumer two hops away (`exporter-propagation`), and an adversarial open-world edge (`exact-type-match`). It ships a distinguished `plausible-cold-pass` control that implements the obvious happy path, passes the public test, and scores 73/100 by omitting exactly those three dimensions -- a deterministic proxy (66-80 band) for the expected unscaffolded/vanilla failure mode, strictly between the 16/100 weak control and the 100/100 references. Built after a v2 canary showed the vanilla control ceilings at 100/100, leaving no headroom.
- A wide-headroom successor `adaptive-contract-evolution-v4` boundary fixture (`implementation/mode-boundary-fixture-v4/`, admission verdict PASS) aimed at the live v3 canary finding: `gpt-5.6-sol` vanilla scored 91/100 and missed only the two-hop `exporter-propagation` consumer, catching every buried single requirement and adversarial edge -- so the model's reliable blind spot is multi-hop / indirect downstream propagation, not stated singles. v4 widens that gap to three independent, all-scaffolding-catchable dimensions worth 35 of 100 points: two indirect two-hop consumer chains through different intermediaries and modules (`exporter-propagation` via `serializer`, `snapshot-propagation` via `digest_helper`) plus a re-run state interaction (`repeat-dedup`, where a replayed unresolved identity must count `unknown_repeat` instead of `unknown_entity_type` again). Its `plausible-cold-pass` control implements the happy path, every bullet, the buried degraded path and the adversarial edge (all caught by the live vanilla arm), passes the public test, and scores 65/100 by omitting exactly those three dimensions -- a deterministic proxy in the declared 55-68 band, strictly between the 11/100 weak control and the 100/100 references. A one-call v4 canary is constructible (zero provider calls, awaiting explicit approval) and has not been run.
- A Fixture Admission Gate (`fixture_admission.py`): a fail-closed semantic validity CLI every NEW ad-hoc campaign fixture must pass before spend. Checks: reference at declared score, second reference (`hidden/reference-alt/`) with declared interpretation differences, negative controls in their score bands, a hostile-candidate battery proving the grader reports every declared dimension under import bombs, first-call exceptions and wrong return types, a host-portability lint (`python3`, `jq`, `npx`, `bash -c`, `/usr/bin/`), and interpretation coverage (explicit registry-miss behavior sentence plus pinned `decision_points`). Preflight and campaign creation refuse to PASS without a fresh admission record.
- A canary spend rule encoded as data (`ablation-design.json` `canary_policy`) and enforcement: a fixture with no prior paid run whose run-record shows `outcome_valid=true` gets a first stage of exactly one call on the cheapest arm; the remaining arms need a separate approval that is only constructible from a canary run-record with `outcome_valid=true`, at least two distinct hidden dimensions and every declared dimension reported.
- UTF-8 subprocess hygiene: every capture in the runners/graders decodes `utf-8` with `errors="replace"` and every CLI reconfigures stdout, eliminating the cp1252 mojibake seen in the invalid campaign summary.
- Semantic serialization grading plus a format-adversary admission check and a process-metrics module, prompted by the live v4 main stage going INVALID: five arms (`vanilla`, `mode-1-lean`, `mode-2-routed`, `full`, canary vanilla) all scored an identical 70/100 because the hidden grader hard-compared exact serialization strings for three dimensions against three mutually inconsistent formats the task never pins. The rewritten `hidden/grade.py` grades those dimensions by CONTENT (registry applied, `schema_version` carried in any format, correct type/id/keys parsed tolerantly) while still rejecting genuine omissions. A new admission check `format-adversary` requires a `hidden/reference-format-alt/` (same substance, deliberately different delimiters/placement) to score 100, and fails admission if the grader is format-brittle -- pointed at the original exact grader it reproduces the 70 and REJECTS it, closing the exact hole before spend. `process_metrics.py` adds a PROCESS instrument alongside the score (consumer enumeration/edit completeness, impact-map section completeness, token cost, and a `self_attestation_gap` boolean: did a run mark its impact-map consumers "verified" while the semantic grade fails a consumer dimension?). The zero-provider re-grade of all five saved runs (`evidence/main-v4-semantic-regrade.json`) shows every arm at 100 semantically -- the arms did the work; the grader measured formatting -- with the only real differences in token cost (`full` ~5.2x main vanilla) and process artifacts (only `full` produced an impact map, gap False = its "verified" claim was truthful). Details in report.md "Semantic grading + process metrics".
- A research-utilization layer making the corpus load-bearing instead of write-only (motivated by the concrete miss: the knowledge base's ~20x harness-cost and strip-scaffolding findings predicted this week's benchmark null result and nobody surfaced them at design time). Three mechanisms: (1) claims->rules traceability (`claims_ledger.py` + `claims-rules-map.json`: 42 material rules linked to 23 claims through 55 links, each claim with source URL/confidence/recheck date; 11 rules recorded honestly `unsupported` with their actual local motivation; validator FAILs on structural problems, WARNs on expired claims and flags dependent rules - the REQ-RES-004 claim-ledger start); (2) decision-time research surfacing (`adaptive_router.py` `decision_type` detection + `findings-index.json`, 21 findings with topic tags and match terms: design/benchmark/architecture prompts get the top topic-matched findings attached to the routing result and Context Pack as `relevant_findings`/`relevant-findings.json`; precision-biased so implementation wording like "must adopt the new contract" never contaminates benchmark arms; mode case `benchmark-design` proves the 20x finding surfaces first, 17/17); (3) a report-only vault hygiene loop (`vault_hygiene.py`: cross-reference integrity, staleness, heuristic contradiction candidates, orphans across Core/, router catalogs, knowledge base, source registry, workstreams, Models and candidate docs; NEVER modifies anything; dated JSON+MD report under evidence/; suite gate = report generated + zero package-level broken references; candidate skill file for a future promoted `/weekly-hygiene` - the REQ-RES-005 drift-detection start). Plus a `--runs-dir` injection for the paid-history scan after live drift (the 2026-07-15 clarity canary) broke the two canary-rule gates that assumed mutable Evals/runs state.
- A spec-first planning layer for underspecified tasks: a fourth selection axis (`clarity`), a spec-synthesis phase (`spec_synthesis.py`: surface inventory, convention inventory, pinned decision points, traceable risk register, rejected approaches, acceptance tests, adversarial spec review), an anti-scope-shrink ledger freeze enforced by the pre-submit gate, a seed-examples knowledge module (`modules/risk-discovery.md`), and a new fixture class measuring exactly this (`implicit-conventions-v1`, `fixture_class: underspecified-by-design`, admitted via class-aware convention-anchor coverage). Grounded in the Hermes DC WIRE experience, the live v4 canary blind spot and the 22-defect postmortem; details in report.md "Spec-first planning layer".
